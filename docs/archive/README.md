# Archived full-product documents

These describe the complete commercial StockControl product. They are **not** the
implementation baseline. The current baseline is the
[demo MVP requirements](../product-requirements.md).

| Document                                                                   | What it is                                                                                                                                                                 |
| -------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [product-requirements-full-v1.md](./product-requirements-full-v1.md)       | Approved full product requirements v1.0 — 18 sections covering purchasing, VAT and costing, serialized tool custody, stocktakes, maps, notifications, and cloud operations |
| [implementation-playbook-full-v1.md](./implementation-playbook-full-v1.md) | The 2,300-line delivery plan for v1.0 — six phases, 24 epics, and the work-packet operating model                                                                          |
| [requirements-traceability-v1.md](./requirements-traceability-v1.md)       | Traceability matrix mapping v1.0 requirements to ADRs, runbooks, and verification obligations                                                                              |

Keep them for two reasons: they are the source to draw from when the demo earns
scope back, and they record decisions that were reasoned about properly rather
than guessed at.

When a capability moves from here into the demo, write it into the demo
requirements as a numbered revision. Do not build directly from these documents —
that is how the demo scope and the product scope quietly merge back together.
