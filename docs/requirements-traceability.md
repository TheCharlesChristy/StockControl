# MVP requirements traceability

This matrix links the approved requirements baseline to architecture,
operations, and planned verification. It does not claim that product features
exist merely because their decision or test obligation is documented.

Status meanings:

- **Foundation**: M0 decision, workflow, or runbook exists.
- **Planned**: implementation and executable acceptance evidence are still
  required.
- **Deferred**: explicitly outside the approved MVP.

## Change control

When an approved requirement changes, update the requirements baseline through
its formal revision process first. Then update affected ADRs (by superseding
them where necessary), implementation, tests, deployment, runbooks, and this
matrix in the same reviewed change. Never change a test alone to make an
unapproved behaviour appear compliant.
