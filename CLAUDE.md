# Working in this repository

StockControl is an inventory system for small businesses with real stock:
what exists, where it is, who moved it, and why. It runs locally with Docker and
in production on Railway. `docs/product-requirements-full.md` is the baseline.

This file is what is not obvious from reading a single file.

## Commands

```bash
pnpm install --frozen-lockfile
pnpm services:up          # PostgreSQL and MinIO
pnpm db:migrate           # explicit; the API never migrates on boot
pnpm db:seed              # demo dataset, generated by the real stock engine
pnpm dev                  # API on :3000, web on :5173

pnpm run quality          # format:check, lint, typecheck, build — run before every commit
pnpm run test:coverage    # unit tests and the coverage floors
pnpm audit --audit-level high
pnpm run test:integration # needs a real PostgreSQL
pnpm run test:e2e         # needs a migrated, seeded database
```

## Layout

```
apps/api        NestJS on Fastify, the process every installation runs
apps/web        React SPA, served by Nginx which also proxies /api
apps/worker     optional; claims assisted-capture jobs, undeployed unless
                STOCK_CAPTURE_ENABLED is on — see
                docs/operations/railway-stock-capture.md
apps/e2e        Playwright
packages/contracts        types and guards shared by both sides
packages/modules/*        framework-free domain logic
packages/platform/*       cross-cutting infrastructure
```

`eslint-plugin-boundaries` enforces the direction of dependencies, so a lint
error about boundaries is a design error, not a config problem. `web` may reach
contracts and modules; `api`/`worker` may reach contracts, modules and platform;
a module may reach contracts and itself. Nothing reaches an app.

## Security invariants

These are the load-bearing ones. Breaking one is not a style question.

- **Authentication is default-closed.** `AuthenticationGuard` is global. A route
  is protected unless it carries `@Public()`, which is visible in review. Adding
  one needs a reason in the pull request.
- **Authorisation happens once, on the server**, through `requireCapability` in
  `apps/api/src/auth/request-context.ts`. The browser hides what a role cannot
  use; that is presentation. Never infer authority from the request body.
- **Production gets no inferred fallback.** `loadPublicAppOrigin` refuses to
  start without an explicit HTTPS origin; the database configuration refuses a
  public host without `sslmode`. Copy that pattern rather than guessing a
  sensible default in production.
- **Never serialise an error message into a log or a response.** Driver errors
  carry connection strings, and connection strings carry passwords. Log the
  error's _name_, plus fields you chose deliberately. `StructuredLogger`
  redacts by key name; do not rely on that alone.
- **Migrations are an explicit release step**, run by a separate database role.
  The API's runtime role cannot change the schema. A migration that adds a table
  must add its grants in `RUNTIME_TABLE_PRIVILEGES`.
- **Uploaded bytes are not trusted.** Validate magic bytes and dimensions, store
  privately, verify the recorded digest when reading back.

## Conventions

- **Comments explain why, never what.** The codebase is deliberate about this:
  a comment earns its place by recording a decision, a trade-off, or a trap —
  something the next reader would otherwise have to rediscover. Do not narrate
  the code beneath it.
- **User-facing text is plain English.** "Those sign-in details were not
  recognised", not "Authentication failed". No jargon a stockroom would not use.
- Strict TypeScript, including `exactOptionalPropertyTypes`. Conditional spreads
  (`...(x === undefined ? {} : { x })`) are the idiom for optional fields.
- Explicit return types on exported functions. `@typescript-eslint/no-unnecessary-condition`
  is on, so a defensive check the types rule out is an error.
- Kysely for all queries. Raw `sql` is for identifiers and expressions the query
  builder cannot express — never for interpolating a value.
- Coverage thresholds are **ratchet floors**. Raise one when a change lifts the
  measured number; never lower one to make a build pass.

## Testing

Tests describe behaviour, not implementation: `it("stops the browser sniffing
an uploaded file into something executable")`. Where a test exists because of a
specific failure mode, say so in a comment above it — that comment is why the
test survives a refactor.

Unit tests run everywhere. `apps/api` reads low on unit coverage because its
controllers and read models are covered by `test:integration` against a real
PostgreSQL and by the browser journey; add to those rather than mocking a
database.
